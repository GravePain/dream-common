# Dream project series: friendly review (29 Oct 2026)

Scope: Dream Forge, Dream Library, Dream World, Dream Paint, Dream Effects, Grave Pain portal. Read-only; nothing changed.
Tone: new hobby project, so this flags what matters and skips style.

## Overall

The series is in good shape for its age. The design choices are sound and consistently applied: one shared library
service with plain files-in-folders and a clear companion convention, a `/dl/` same-origin proxy in every tool so no
browser code hard-codes the library address, palette-by-role colouring so any palette fits any generator, seeded
randomness everywhere, and dependency-free servers. Dream World's three.js side (instanced LOD batching, splat terrain,
undo commands) is well engineered, and it type-checks clean under strict TypeScript. Code is readable and comments say why.

The weak spots are the kind that come from moving fast: a few real bugs, the small servers are five copies of one file
(so every fix is made five times), the LAN-facing surface is wider than intended, and there are no tests or API docs.

## A. Fix soon (real bugs, all small)

1. **Every tool server dies on one malformed URL.** `decodeURIComponent` runs outside any try/catch in
   Forge, Paint, Effects (`server.mjs:28`) and Library (`server.mjs:250`). `GET /%` exits the process (confirmed).
   Action: wrap the request handler in try/catch returning 400. Do it once in the shared module (C1).
2. **Forge "From a photo" throws on the second render.** `phototex.js:31` returns the bare canvas on a cache hit but
   `:71` returns the cache object; `level()` then reads `.levels` of a canvas. Save/Download of any photo texture hits it.
   Action: `return cache` on line 31.
3. **Library never lists versions of effects, scenes or palettes.** `writePiece` keeps `v1.fx.json`, but
   `/api/versions` (`server.mjs:200`) matches `^v(\d+)\.json$`. Action: one `pieceExt(name)` helper used by both.
4. **Library versioning can overwrite an old version.** Next version number comes from the meta, not the folder
   (`server.mjs:113`); a missing or hand-edited meta makes `n` = 1 again and rename clobbers `v1.glb` silently.
   Action: `n = max(existing vN) + 1`, and never rename onto an existing path.
5. **Dream World `startup.bat` can't start on a fresh checkout.** Lines 20-23 still run `tools\build_assets.py`
   (paid packs at hard-coded `K:/` paths) when a manifest nothing reads any more is missing. Action: delete those lines,
   plus the `assets` npm script, the `/assets/ui/fonts` `@font-face` 404s, and the dead `review.html` / `review.ts` /
   `review_packs.py`.
6. **Forge: a generator that throws in `build()` leaves the UI half-switched.** `main.js:100`. Action: try/catch in
   `rebuild()`, flag the generator like import failures already are.
7. **Dream World gives no signal when the library is down.** Fetch failures become `[]` (`manifest.ts:27`,
   `effects.ts:378`), so you get empty shelves and flat ground. Action: toast "Dream Library (5230) not reachable".
   Also await `connectLibrary` before enabling Save (`main.js:143`).

## B. Tighten the LAN surface (small to medium)

8. **Library: any web page on any LAN machine can read files off the library PC.** CORS `*` + unauthenticated
   `POST /api/places` + `GET /api/file` serving anything inside a place. Action: make places config-file-only (edit
   `library.json` by hand) or check `Origin` against the known tool origins before mutating routes; serve only known
   kinds and companions from `/api/file`.
9. **`?library=<url>` loads remote JavaScript.** Forge `main.js:16`, Paint `main.js:6`, Effects `main.js:8`,
   Characters too. Action: drop the override (the `/dl/` proxy and `DREAM_LIBRARY` env already cover the use case).
10. **`.git` / `.claude` block is case-sensitive on a case-insensitive disk.** `GET /.GIT/config` serves the real
    file (confirmed). Action: block any path segment starting with `.`, in the shared module.
11. **Every `/dl/` proxy (and Dream World's Vite proxy) relays writes and deletes from anyone on the LAN.** Fine at
    home, but HOSTING.md puts these online. Action: proxy allowlist (GET `/api/*`, the shared JS files) with writes
    allowed only from loopback or a configured admin list; say so in HOSTING.md.
12. **Dream World gallery: no total size cap, and the host isn't admin via its LAN address.** `server/gallery.ts:8,28`.
    Action: cap `gallery/` size and posts per address per hour; `GALLERY_ADMIN` env allowlist.
13. **Library `/api/save` ignores `readonly` and lets a name collide with companions** (`server.mjs:187`).
    Action: 400 on readonly place 0; reject `ext` that is a companion suffix.

## C. Shared plumbing (one medium job that pays for itself)

14. **Five near-identical `server.mjs` files.** Forge, Paint, Effects, Characters are byte-identical apart from name
    and port; the Library repeats the static branch. Items 1, 10, 11 each need doing five times today.
    Action: `serveFolder(dir, { port, name, libraryProxy })` in `dream-library/public/serve.mjs` (or a small
    `dream-common`), each tool's `server.mjs` shrinking to three lines. Add a `/config.json` there listing sibling
    URLs so the hard-coded portal (5170) and Paint (5250) links in every page go away.
15. **Library listing is re-implemented in each tool and rescanned on every call.** Forge fetches places then list
    per place twice at startup and after every save; Dream World does it three ways (`manifest.ts`, `effects.ts`,
    `scenes.ts`); the Library itself rescans 5000-item CC0 packs per request and truncates silently.
    Action: library caches scans per place by directory mtime and returns `truncated: true`; `/api/list?kind=`;
    one `listLibrary()` in `library.js` the tools share.
16. **Place ids are array indexes.** Deleting a place renumbers the rest and breaks every saved `?scene=2|path`
    link. Action: a stable slug `id` per place in `library.json`, accepted alongside the index.
17. **Three tools import three.js from unpkg.** Paint and Effects go blank offline. Action: vendor
    `three.module.js` under `dream-library/public/vendor/` and point import maps at `/dl/vendor/`.

## D. Hygiene

18. **Dream Paint, Dream Effects and the portal have no GitHub remote.** They exist only on this PC and Morty.
    Action: create the repos and push, same flow as Forge. The portal also has no `.gitignore`.
19. **No tests anywhere.** The hard parts are pure functions: Forge `mesh.js` (extrude, subdivide, compact),
    `texlib.js` wrap-around noise, Library save → version → list, Dream World `save.ts` migration and gallery regex.
    Action: one `node --test` file per repo, a dozen cases each, run by hand for now.
20. **API contract lives in code comments.** Four modules depend on the Library's request and response shapes, and
    its error codes vary (plain-text 404 on `file`, 500 for bad JSON, bad `ext` silently becomes `.glb`).
    Action: an API section in the Library README with shapes and codes; validate inputs and always answer `{error}`.
21. **Big files.** Forge `main.js` (1,213 lines) and Dream World `main.ts` (1,335 lines) hold everything. Action, when
    convenient: peel off paint, library UI, gizmo, persistence and gallery UI into their own modules. Mechanical.
22. **Leftovers.** Dream World still shows the Cyber kit switch and tower/neon tools the library never fills; `plain()`
    is copy-pasted into six Forge generators and `fallen-log` rolls its own material. Action: drop the kit switch,
    export `plain` from `gen.js`.
23. **Docs.** READMEs don't say a tool needs the library running first, what `DREAM_LIBRARY` does, that servers bind all
    interfaces, or which files each tool writes and who reads them. HOSTING.md's layout table lists only World Builder
    and Skyfall. Action: a "Needs" and a "Files it writes" line per README; a row per Dream tool in HOSTING.md.
